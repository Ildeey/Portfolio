# План действий — механические шаги и описание для генерации кода

Ниже — детальный пошаговый план действий по каждому пункту вашего запроса. Фокус на "механических" шагах, которые вы будете выполнять на хостинге и локально, и на чётком описании того, какой код будет сгенерирован (файлы/эндпойнты/схема БД). Не пишем код сразу — сначала вы выполняете эти шаги, затем генерируем соответствующие файлы в согласованном формате.

## Общее (требования и предпосылки)
- Хостинг: Beget (PHP + MySQL). Доступ к панели управления и FTP/SFTP, phpMyAdmin.
- Локальная подготовка: текстовый редактор/VS Code, PHP (для локального теста можно использовать встроенный сервер `php -S`), MySQL (или MariaDB) локально.
- Бэкап: перед изменениями делайте резервную копию текущих файлов сайта и базы данных.

## 2) Регистрация и вход (пользователь vs админ)
Цели: два типа аккаунтов — `user` и `admin`. Пользователь может отправлять запросы (форма "доступен к работе"), админ может добавлять проекты.

Механические шаги (пользовательские операции и админские):
1. Создать таблицу `users` в MySQL (схема ниже). Через phpMyAdmin можно импортировать SQL.
2. Создать таблицу `projects` (схема ниже).
3. Подготовить `admin.html` (страница входа/личный кабинет) и клиентскую логику для отправки форм — это уже частично сделано локально.
4. На `index.html` заменить кнопку "доступен к работе" на отправку POST-запроса к `/api/request` (серверный PHP-обработчик) — либо открывать модальное окно для незарегистрированных пользователей.
5. Админ входит через `/admin.html` — после входа админ видит кнопку "Добавить проект" вместо "Доступен к работе" (или отдельную админ-страницу), заполняет мини-форму (категория, название, описание, файл изображения) -> отправка на `/api/projects/create`.

Описание для генерации кода (эндпойнты и файлы):
- `api/config.php` — подключение к БД (импортирует `config.php`).
- `api/auth.php` — эндпойнты: `POST /api/auth/register` (регистрация), `POST /api/auth/login` (возвращает сессию или JWT), `POST /api/auth/logout`.
- `api/request.php` — `POST /api/request` — сохраняет заявку пользователя (связь с users или гостевая заявка).
- `api/projects.php` — методы: `GET /api/projects` (список), `POST /api/projects/create` (создать, доступно только admin), `DELETE /api/projects/{id}`, `PATCH /api/projects/{id}`.
- `uploads/` — директория для загружаемых изображений; генерируем безопасные имена и сохраняем путь в `projects.image`.

Схема БД (минимальная):
```sql
-- users
CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(100) UNIQUE,
  email VARCHAR(255) UNIQUE,
  password_hash VARCHAR(255),
  phone VARCHAR(50),
  role ENUM('user','admin') DEFAULT 'user',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- projects
CREATE TABLE projects (
  id INT AUTO_INCREMENT PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  category VARCHAR(100) NOT NULL,
  description TEXT,
  image VARCHAR(255),
  created_by INT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE SET NULL
);

-- requests (заявки от пользователей)
CREATE TABLE requests (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NULL,
  name VARCHAR(255),
  email VARCHAR(255),
  phone VARCHAR(50),
  message TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);
```

Описание логики аутентификации (безопасно):
- Сервер (PHP) хранит `password_hash` (функция `password_hash()`), сравнение `password_verify()`.
- Для сессий можно использовать PHP-сессии (`session_start()` + установка `$_SESSION['user_id']`) либо JWT (если предпочтительнее stateless). Для простоты и совместимости с Beget рекомендуем PHP-сессии.
- Все admin-эндпойнты проверяют роль пользователя (см. `is_admin()` helper).

## 3) Две базы данных — учетные записи и проекты
Пояснение: обычно достаточно одной MySQL- БД с несколькими таблицами (users, projects, requests). Но если вы принципиально хотите разделить, можно создать две БД: `portfolio_auth` и `portfolio_content`.

Механические шаги (если две БД):
1. Через панель Beget создайте две базы данных и соответствующих пользователей.
2. Залейте SQL-схемы: `users` в первую, `projects` и `requests` во вторую.
3. В `config.php` добавьте два набора констант: DB_AUTH_* и DB_CONTENT_* и реализуйте два PDO-подключения (`$pdoAuth`, `$pdoContent`).

Описание для генерации кода:
- `api/db.php` — фабрика подключений: возвращает два PDO-объекта при необходимости.
- Все SQL-запросы используют подготовленные выражения (`$pdo->prepare(...)`).

Замечание: проще и удобнее — одна БД с префиксами таблиц; экономит ресурсы и упрощает бэкапы.

## Безопасность и производственные рекомендации
- Всегда хранить `config.php` вне публичной ветки/репозитория.
- Хеширование паролей: `password_hash()` / `password_verify()`.
- Использовать подготовленные выражения (PDO) для всех SQL-запросов.
- Проверять типы и размеры загружаемых файлов, ограничивать допустимые форматы (jpg, png, webp) и размер (например, 3–5 MB).
- Защита от CSRF: при вводе форм использовать токены, проверяемые на сервере (для критичных POST-запросов).
- Минимизировать публичный доступ к админ-маршрутам: требовать авторизацию и проверку роли.

## Тестирование и деплой
Механические шаги для тестирования локально и деплоя:
1. Локально: запустите сервер `php -S localhost:8000` и используйте локальную MySQL. Смоделируйте операции регистрации/входа/создания проекта.
2. Подготовьте дамп SQL с тестовыми данными (phpMyAdmin -> Export).
3. На Beget: создайте базы, импортируйте дамп через phpMyAdmin.
4. Загрузите файлы сайта и установите права на папки `uploads/`.
5. Проверьте работу регистраций, входа и добавления проекта (через админ-панель).

Короткий чеклист перед публикацией:
- SSL включён.
- Файл `config.php` содержит живые данные БД.
- Права на `uploads/` корректны.
- Пароли админа и пользователей хешированы.
